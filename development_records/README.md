# RecycleAI 开发记录使用说明

用途：香港教育大学 INT6065 Artificial Intelligence in Education 小组展示与反思。记录开发事实，不代替课程原始要求。

## 从哪里开始

- [PPT 素材汇总](PPT_MATERIALS.md)：按七个展示主题选材料。
- [历史阶段索引](HISTORY.md)：区分已有证据和待补充阶段。
- 每日记录：[10月29日](daily/2026-10-29.md)、[10月30日](daily/2026-10-30.md)、[10月31日](daily/2026-10-31.md)。
- [日志模板](DAILY_TEMPLATE.md)、[截图索引及手动取证清单](screenshots/README.md)。
- 原开发记录继续引用 [DEVELOPMENT_LOG.md](../DEVELOPMENT_LOG.md)、[TEST_RESULTS.md](../TEST_RESULTS.md) 和 [readme.txt](../readme.txt)，不删除或重复改写全文。检查时没有找到既有 PROMPTS.md、CHANGELOG.md 或 TEST_LOG.md。

## 以后每次开发怎么用

正常告诉 Codex 要修改什么即可。项目根目录 AGENTS.md 要求每次任务完成前更新当天日志及 PPT_MATERIALS.md，无需每次重复说明。使用上海时区日期；同一天只维护一份 YYYY-MM-DD.md，按任务 A/B/C 的真实先后顺序追加到六个固定栏目，保留之前的失败和修正记录。

重要 Prompt 在 prompts/ 中按日期和序号原文保存，每日日志第二栏按顺序引用。这里只保留用户实际提交的文字，不记录 AI 内部推理或伪造的对话。历史缺失写“原始 Prompt 待补充”；截图缺失写“待补充”。当前保存的四份原始 Prompt 来自本次聊天可见消息，日期依据对应消息的客户端日期，不虚构时分秒。

输入“今天收工，整理开发记录”时，Codex 应检查当日六栏、Prompt、截图、测试状态、PPT 引用和提交状态，补齐可核实内容，并输出简短总结及未完成清单。没有证据的内容继续保留待补充，不自动运行收费 API，不自动 Commit 或 Push。

这套“自动”指在后续 Codex 开发任务中依照规范更新文件，不是后台定时器，也不会自动抓取其他聊天或网页。Codex 无法获取的对话截图、课堂反馈仍需你提供或手动保存。

## 证据标准

每项结论注明来源：Git 提交、实际工具执行、现有文档或用户原始需求。文档记载的历史测试与本次亲自执行的测试分开描述。Git 提交日期不能当开发发生日期；磁盘修改时间不证明功能开发日期。

测试分为通过、失败后修正、尚未测试；另注明演示、离线模拟、浏览器到本地后端或真实供应商 API。模拟正确结果不是 AI 准确率，合成 60 分不是实际完成六道测验。单次截图不能证明所有功能或真实用户学习效果。

截图用真实浏览器或真实应用捕获，文件名采用 YYYY-MM-DD_内容.png。重名时加 _02，不覆盖原证据。每份截图注明日期依据、页面状态、版本、是否调用真实 API；复制旧截图不改变其历史归属。不用 AI 生成截图，不把本地演示命名为 api_success。

新日志用相对路径引用截图，例如 `../screenshots/2026-10-31_local_demo_banana.png`。PPT 中可注明“Local demo”或“Mock API test”。本次迁移和记录机制尚未提交，不编造 Commit Hash；现有 8016f95 只代表原 Gemini/规范基线。

## 安全及保存

禁止记录或上传 .env、真实 Key、密码、Cookie、令牌及个人隐私。Prompt 有敏感值时以 `[已脱敏]` 替换敏感片段，并标明脱敏，不改动其余内容；不保存含密钥的原始副本。截图前关闭配置文件、账户和个人信息；有敏感内容先遮挡再保存。不要整屏拍到其他应用的隐私。

每日结束由你在 GitHub Desktop 检查 Changes，提交并推送；未经确认 Codex 不代为执行。提交后下次可让 Codex补记实际 Commit Hash。仅正文中提到 API Key 变量名不代表含真实密钥，仍需人工核对。

当前机制建立在 main 原目录。gemini-version 为冻结备份，未自动向其复制新规范；未来若在其他分支继续开发，应先明确是否需要同步这套记录规范。
